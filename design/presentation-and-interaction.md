# Presentation and interaction

The illustrated isometric map is the primary place view. Walking within town is free; selecting a venue or person opens a preview before any paid/time-consuming activity. Camera and input guards prevent stale gestures from selecting the wrong context.

People respond with short direct speech and a visible portrait/action cue. Current venue and activity context must be truthful; a remote conversation is labeled remote. Longer narrative and prior receipts belong in optional disclosures, not the primary response. Only Mina, Jo and Eli currently have situational facial-expression packs.

Ordinary confirmed actions show a quick contextual player reaction. Persisted familiarity progresses through first, familiar, routine and custom, with stable variants and no immediate repeat. An authoritative chance incident may add a short actual-result vignette. Failed or pending commands never show success.

Semantic audio fires once after authoritative acceptance. Coffee uses a sip recording; action-specific recordings and source licenses are documented in `docs/SEMANTIC-AUDIO.md`. Mute and volume persist, autoplay waits for a user gesture, and duplicate receipts do not repeat cues. A code assertion is not an audible listening test.

Progress uses qualitative states. Exact cash, prices, paid hours and priority blocks remain visible for practical choices. Hidden stat quantities, thresholds and deltas do not belong in tooltips, ARIA labels or optional player-facing details.

See the renderer, save and verification docs for interrupted navigation, reduced-motion, keyboard, image-failure and live mobile test boundaries.
