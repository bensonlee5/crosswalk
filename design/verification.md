# Verification

Run the commands in [development](development.md) against the final source, sequentially where memory is constrained. Reports for an earlier commit do not prove the current release.

Required boundaries:
- Fresh 1–4-player lives through the eight-month ending; current role/application/acceptance/work/training and arrears behavior.
- Preview versus actual effects, chance-event exact receipts, deterministic retry, private histories and shared opportunity contention.
- Authenticated ownership, stale versions, duplicate request IDs, failure before/after commit, other-seat masking and PostgreSQL transaction rollback.
- Home restore/history, sign-out or owner switch during delayed responses, pending intent recovery, unsupported saves and current protocol checks.
- Map routes, actor/guardian picking, visible labels, interrupted movement, teardown, reduced motion and image failure.
- Reproducible Travel Guide, internal links, all 68 portraits, venue names, item/brand links and engine-copy hashes.

Keep useful regression coverage when removing obsolete adapters. Do not retain an unused production backend solely to support a test harness. Use the actual service with a bounded test storage seam, plus real PostgreSQL tests for transaction semantics.

Public browser QA supplements tests. Desktop cloud coverage is not native mobile or audible playback verification.
